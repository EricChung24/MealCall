# MealCall 庫存優先首頁與管理員權限設計

## 目標

使用者登入後先處理共用冰箱庫存，再查看三餐安排。管理員可在專屬後台查看並管理所有家庭會員的角色與逐項權限。

## 字體

全站優先使用 Apple 蘋方體：`PingFang TC`、`PingFang SC`；非 Apple 裝置使用 `Microsoft JhengHei` 或系統無襯線字體作為備援。

## 首頁布局

首頁順序：頂部導覽、庫存摘要、需要補貨、目前庫存、今日三餐。

- 庫存摘要顯示可用食材總數、已保留數量、需要補貨數量。
- 「新增食材」與「調整庫存」在摘要區直接可用。
- 需要補貨項目用紅色狀態卡片置頂，可直接增加數量。
- 目前庫存支援搜尋、分類篩選，以及每項食材的 `−／數量／＋` 操作。
- 三餐區位於庫存下方，可切換今天、明天、後天。
- 桌機使用左右分欄，手機使用單欄排列。

## 庫存邏輯

```txt
可用量 = 總庫存 - 已發布餐點的保留量
```

新增食材需要名稱、分類、單位、目前數量與安全庫存。調整數量不可低於 0；可用量低於安全庫存時顯示「需要補貨」。被餐點保留中的食材不能直接刪除，必須先取消相關餐點。

所有庫存操作成功後立即更新 Supabase 與首頁顯示；失敗時保留表單內容並顯示錯誤訊息。

## 管理員會員權限清單

只有 `lf2net679@yahoo.com.tw` 能看到管理員後台及其入口。後台列出同一家庭的所有會員，顯示 Email、名稱、角色名稱與權限開關。

可管理的逐項權限：

- 查看看板
- 查看庫存
- 新增食材
- 調整庫存
- 建立餐點
- 發布餐點
- 完成／取消餐點
- 管理會員
- 管理角色

管理員可以新增角色、修改角色名稱、將角色套用給會員、直接調整單一會員權限，以及移除家庭會員。RLS 必須在資料庫層再次驗證管理員資格與家庭成員範圍。

## 餐點日期

日期選擇使用台灣時區的實際日期，提供今天、明天、後天切換；看板只顯示目前選取日期的餐點，建立餐點時沿用選取日期。

## 驗收情境

1. 登入後首頁先看到庫存與補貨狀態。
2. 新增食材、增加／減少數量後重新整理仍保留。
3. 已保留食材的可用量正確扣除。
4. 點擊今天／明天／後天會切換對應餐點。
5. 管理員能看到所有會員與逐項權限；一般會員不能進入。
6. 桌機與手機布局都能直接找到主要操作。
